# FLISP Assembly for VS Code

Syntax highlighting — and assembling with `qaflisp` — for the assembly language of the FLISP processor (FLexible Instruction Set Processor), as used in the Grudat labs with DigiFlisp.

The grammar follows the *FLISP-Handbok* (version 2025-12-09) and the behaviour of the `qaflisp` assembler (version 1.3).
## What gets highlighted

**`.sflisp` (source code)**

| Element | Example |
|---|---|
| Comments | `; text to end of line` and everything after the operand (see below) |
| Labels | name in column 1, optionally followed by `:` |
| Assembler directives | `ORG`, `EQU`, `FCB`, `FCS`, `RMB`, `END` |
| Flow-control instructions | `JMP`, `JSR`, `BSR`, `BRA`, `RTS`, `RTI`, all `B…` branches |
| Other instructions | the complete set from the FLISP handbook, plus the aliases `ASLA`/`ASL`, `PSHCC`, `PULCC` |
| Lab instructions | `MOVE`, `CMJEQ` — own scope, *italic and underlined* |
| Numbers | `$3F` hex, `%01000000` binary, `42` decimal, `'A'` character |
| Immediate | `#` |
| Registers | `A`, `X`, `Y`, `SP`, `PC`, `CC` |
| Indexed addressing | `n,SP` · `n,X` · `A,Y` · `,X+` · `,X-` · `,+Y` · `,-Y` |
| Strings | `"TEXT"` for `FCS` |
| Errors | a mnemonic in column 1 (qaflisp reads it as a label: *Illegal mnemonic*) |

**`.fmem` (memory image, generated by qaflisp)** — `#setMemory` directives with address and value; `# ClearAllMemory` and `# ClearAllRegisters` with their own highlighting (scope `keyword.control.reset`); the header lines are shown as comments.

### Line structure and comments

qaflisp reads every line as `[Label] Mnemonic [Operand] [Comment]`:

- Column 1 is always a label. An instruction must be indented.
- The operand ends at the first space (except inside a string). Everything after it is a comment, even without `;`.
- For instructions without an operand (`NOP`, `PSHA`, `RTS`, `INCA` …) and for `END`, everything after the mnemonic is a comment.

The grammar does the same. This has a practical consequence: `LDA #K + 1` loads `K`, not `K+1` — the ` + 1` is a comment and is shown in grey. Write `LDA #K+1` instead.

### Lab instructions

`MOVE` and `CMJEQ` are not standard instructions; neither the handbook nor qaflisp knows them. They get the scope `entity.name.type.instruction.custom.flisp`, which the extension renders *italic and underlined* by default so they stand out in every theme.

If you set `editor.tokenColorCustomizations.textMateRules` in your own settings, that replaces this default. In that case, add the rule there:

```json
"editor.tokenColorCustomizations": {
  "textMateRules": [
    { "scope": "entity.name.type.instruction.custom.flisp", "settings": { "fontStyle": "italic underline" } }
  ]
}
```

## Assembling

The extension runs the `qaflisp` assembler on the current file and shows its errors directly in the editor. **qaflisp is not included** — you need your own copy of `qaflisp.exe`.

- **Run it:** the ▶ button in the editor title bar, `F7`, *FLISP: Assemble* in the command palette, or right-click a `.sflisp` file in the Explorer. Unsaved changes are saved first.
- **Errors and warnings** are underlined in the source and listed in the *Problems* panel. The full qaflisp output is in the *FLISP* output channel.
- **Output files** (`.s19`, `.lst`, `.fmem`) are written next to the source file. Load the `.fmem` into DigiFlisp.

### Where qaflisp is looked for

1. the path in the `flisp.qaflispPath` setting — if set, nothing else is tried;
2. the source file's folder and its parent folders, up to the workspace folder;
3. the workspace folders;
4. the `PATH`.

So putting `qaflisp.exe` in the top folder of your workspace is enough. If it is not found, a message offers to pick it with a file dialog.

### Settings

| Setting | Default | Meaning |
|---|---|---|
| `flisp.qaflispPath` | empty | path to `qaflisp.exe` |
| `flisp.assembleOnSave` | `false` | assemble automatically on every save |
| `flisp.listFile` | `true` | create a `.lst` list file (`-L`) |
| `flisp.warnings` | `true` | report warnings (`-w`) |
| `flisp.debugInfo` | `false` | generate source-level debug information (`-g`) |

Assembling runs an external program and is therefore disabled in [untrusted workspaces](https://code.visualstudio.com/docs/editor/workspace-trust); highlighting works everywhere.

## Installation

Without the Marketplace, in one of two ways:

**As a `.vsix`** — in VS Code press `Ctrl+Shift+P` → *Extensions: Install from VSIX…* → select the file.

**As a folder** — copy the `flisp-asm-src` folder here and restart VS Code:

- Windows: `%USERPROFILE%\.vscode\extensions\`
- macOS/Linux: `~/.vscode/extensions/`

Requires VS Code 1.63 or later.

## Building

Requires Node.js 20 or later.

```bash
npm install          # fetches vsce and the test libraries
npm test             # unit tests for the qaflisp integration, then the grammar tests
npm run package      # creates flisp-asm-<version>.vsix
```

The `.vsix` ends up in the project folder. `.vscodeignore` keeps `test/` and `node_modules/` out of the package.

To develop without packaging: open the folder in VS Code and press `F5`. This launches a second VS Code window with the extension loaded — open a `.sflisp` file there and check the highlighting directly.

### The tests

`test/qaflisp-test.js` tests the qaflisp integration (`src/qaflisp.js`) without VS Code: parsing of qaflisp's messages, the command-line flags and the search order. If a real `qaflisp.exe` is found above the project folder or on the `PATH`, it also assembles a correct and a broken file with it; otherwise those two cases are skipped.

`test/tokenize-test.js` loads the grammar with the same engine VS Code uses (`vscode-textmate` plus `vscode-oniguruma`), tokenizes the sample files and, for each expectation, checks one specific token on one specific line. The cases are in the `expectations` list at the top of the script; adding one is a single line:

```js
// [file, unique snippet of the line, exact token text, scope prefix]
['sample.sflisp', 'CMPA    #2', 'CMPA', 'keyword.other.instruction'],
// '!' before the scope: the token must NOT have this scope
['sample.sflisp', 'BEQ     Start', 'Start', '!entity.name.function.label'],
```

`test/sample.fmem` is real qaflisp output. `test/sample.sflisp` assembles with qaflisp without errors, except for the lab instructions and the deliberately wrong line `LDA #1` in column 1.

### Inspecting scopes in the editor

If a colour looks wrong: `Ctrl+Shift+P` → *Developer: Inspect Editor Tokens and Scopes*, then put the cursor on the character in question. VS Code shows which scope applies there — that tells you which rule matched.

## Customizing

The grammar is in `syntaxes/flisp.tmLanguage.json`. A new custom instruction goes in two places:

1. in `statement-operand`, group 3 (`MOVE|CMJEQ`) — or in `statement-inherent` if it takes no operand,
2. in the list of the first `label` rule, so that it is flagged as an error in column 1.

Colours come from the active VS Code theme, not from the extension, so directives and instructions look different depending on the theme. Instructions use the scope `keyword.other.instruction` and are therefore coloured in practically every theme; in the default *Dark+* theme, however, they share their colour with the directives.

## Limitations

No autocompletion and no debugger. Errors are only checked when you assemble, not while you type. Assembling needs your own copy of qaflisp; it is Windows-only. Use DigiFlisp to run and debug the program.
